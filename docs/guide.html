なぜ通常の Wi-Fi では見えず、Nexmon CSI だと「在室」や「窓の開閉」が分かるのか？

通常の Wi-Fi（RSSI）は 256本の電波（サブキャリア）を全部平均した「1個の強さ」 しか見ません。そのため、部屋の隅で人が動いたり窓が開いたりして一部の周波数だけ反射が変わっても、平均値に埋もれてしまいます。

Nexmon CSI（Channel State Information） は、Wi-Fi チップのファームウェア内部から 256本（80MHz幅）すべての複素振幅（振幅 + 位相） を取り出します。下のシミュレータで状態を切り替えて違いを体感してみてください。

Raspberry Pi 4B × Nexmon CSI の3層アーキテクチャ

Nexmon CSI は通常のアプリではなく、① Wi-Fi チップ内部のファームウェア → ② Linux カーネルドライバ → ③ ユーザー空間のコマンド群 の3層がすべて噛み合って初めて動きます。

今回の構築で遭遇した5つの難所と、解決した理由

難所 1：パッチバージョンの罠

7_45_206 でビルドエラー → 7_45_189 が正解だった

Pi の初期ファームウェアは 7.45.241 でしたが、最新の nexmon_csi は 7_45_189 用バイナリをベースにパッチを生成して置き換える方式 になっていました（7_45_206 には version.c 用シンボルの不一致があり失敗）。また Makefile.rpi は Debian Bookworm（NetworkManager + brcmfmac_cyw）向けだったため、Bullseye 5.10 では従来 Makefile が必要でした。

難所 2：カーネルヘッダのバージョン不一致

apt install raspberrypi-kernel-headers が拒否された → pool から 1.20220120-1 を直接取得

実行中のカーネルは 5.10.92-v7l+（1:1.20220120-1）でしたが、apt リポジトリ上の最新ヘッダは別バージョン（1:1.20230405-1）に更新済みでした。もし hold せず入れていたらカーネルモジュールがビルドできなくなるところでした。archive.raspberrypi.org/debian/pool/... から完全一致版の .deb を落として dpkg -i で入れ、再度 apt-mark hold したことで解決しました。

難所 3：Bullseye の Python 3 化

b43-beautifier が SyntaxError → python2 導入と shebang 置換

マイクロコード逆アセンブラ b43-beautifier は Python 2 の print "..." 構文で書かれていますが、Bullseye の /usr/bin/python は Python 3.9 を指していました。python2 をインストールし、~/nexmon/buildtools/ 内の #!/usr/bin/env python を python2 へ書き換えて解決しました。

難所 4：wlan0 自動ダウンと再起動時の消失

dhcpcd が wlan0 を落とす / make install-firmware は一時的な insmod のみ

① wpa_supplicant を止めると dhcpcd が検知して wlan0 を DOWN にしてしまうため、/etc/dhcpcd.conf に denyinterfaces wlan0 mon0 を追加しました。② make install-firmware は再起動すると元の brcmfmac.ko に戻るため、/lib/modules/5.10.92-v7l+/.../brcmfmac.ko を上書きして depmod -a で永続化しました。

難所 5：再起動後の 169.254.x.x と Tailscale の nftables

DHCP タイムアウトでネット不通 → 有線 eth0 を固定 IP 化し、iptables-legacy に切替

再起動時にルーターの DHCP 応答が間に合わず eth0 がリンクローカル（169.254.181.195）になり Tailscale がインターネットに出られませんでした。/etc/dhcpcd.conf で eth0 を 192.168.10.2/24（GW 192.168.10.1）に固定し、カーネル 5.10 と相性の良い iptables-legacy に切り替えたことで、再起動後も 100.68.123.109 で即オンラインになります。
